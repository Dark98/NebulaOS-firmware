# Boot Warning Audit

Structured inventory of every warning/error in the custom Nebula Pad Linux 6.6.18-rt23 kernel boot
log, per the "Nebula Pad Linux 6.6 boot-cleanup investigation and remediation" mission (2026-07-23).
Baseline: `artifacts/parity/baseline-2026-07-23-boot-cleanup/` (git commits, config/artifact hashes,
full `dmesg` capture). Evidence for every row below is a direct source-code citation or a live
stock/custom comparison - no message is classified from guesswork.

Log scope note: the captured log runs from cold boot through `Run /linuxrc as init process` only
(dmesg's own natural end point, before userspace). Userspace-stage validation (Wi-Fi association,
DHCP, Moonraker, Klipper, GuppyScreen, `confirm-good`, clean shutdown) is a separate, already-proven
capability documented in FIRMWARE.md and re-confirmed live at baseline time (see `BASELINE.md`).

## Summary of open work from this inventory

Confirmed real, fixable issues (in priority order, most evidence-complete first):

1. **`ingenic_mac.c` GPIO error-pointer bug + real `GPB-16` pin conflict with `lcd_rst`** - both the
   driver bug (Phase 2) and the board-level fix (Phase 12, disable unpopulated `&mac1`) are fully
   evidenced and ready to implement as two isolated commits.
2. **`regulatory.db` packaging** (Phase 5) - confirmed absent, straightforward Buildroot overlay fix.
3. **`brcmfmac` board-specific firmware alias symlink** (Phase 6) - confirmed absent, one-line overlay fix.
4. **DMIC DAI link churn** (Phase 11) - candidate fix identified (disable only the DMIC DAI link, not
   the working audio infrastructure around it), not yet implemented.
5. **Framebuffer swap-property DT annotation** (Phase 15) - candidate fix identified, not yet implemented.

Still needs live tracing, not yet root-caused:

- The `sdhci_ingenic_probe`/`ingenic_gpio_request` "redefinition" backtrace on `GPD` (Phase 3) - a
  different call chain than the GMAC finding, not yet traced to a specific consumer/pin.
- SFC "unknown flash type" (Phase 9) - real ambiguity about whether SPI-NOR is physically populated
  on this board revision; no blind-probe method available per the mission's own safety rules.

Closed, no action needed:

- Backup GPT warning (`STOCK_STORAGE_LAYOUT_LIMITATION`, confirmed identical on stock).
- Jitterentropy (`ARCHITECTURE_LIMITATION`, hardware TRNG covers it, CRNG healthy).
- USB dummy regulators, MScaler IRQs, TCU trigger IRQ, `pdmam` IRQ (`OPTIONAL_FEATURE_MISSING`,
  SoC-reference-level omissions with no proven consumer impact).
- Architecture memory-protection message (`ARCHITECTURE_LIMITATION`, confirmed via mainline source).
- `uart3`/`i2c4` conflict, initial unpowered Wi-Fi scan (already tracked/classified by prior work).
